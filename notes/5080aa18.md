Every predicate in this forest is built from sums and products of the
coefficients. Incidence is a [[f7e286b8|The left contraction is the metric projection]] against a blade, distance is a
[[79ec6893|The scalar product reads off a single number]], intersection is an
[[8e33745c|wedge]], and a transformation is a [[dc7fd3f4|The sandwich is an algebra automorphism]]. The only
non-polynomial operations are the final square roots and trigonometric
functions inside a constructor.

This matters because polynomial residuals are exactly what automatic
differentiation wants. There is no case analysis on which object type you have,
no coordinate-frame bookkeeping, and no branching on tensor values, so the
whole expression is a straight-line program over `Nx` and it differentiates and
compiles ([[863e305f|Traced algebra: no host branches]]).

```ocaml
open Geom

let residual p =
  let x = Cga.point p in
  let pi =
    Cga.plane ~normal:(Nx.create Nx.float32 [|3|] [|0.;0.;1.|])
      ~offset:(Nx.scalar Nx.float32 1.)
  in
  Cga.scalar_prod x pi

let value, grad = Rune.value_and_grad' residual
                    (Nx.create Nx.float32 [|3|] [|0.; 0.; 2.|])
(* value 1., grad [|0.; 0.; 1.|] : the signed distance and its gradient *)
```

That example is a signed point-to-plane distance: $X dot pi = z - 1$ for a
point at height $z$ and the plane $z = 1$ ([[7d7f29a7|A plane is a vector]]). Its gradient is the
plane normal; that is not a coincidence, it is the reason these residuals are
good objectives ([[97e5b2c5|Write task objectives as conformal residuals]]). The price is [[1d3a2467|numerical care]]:
projective representations carry a scale, and a residual that is polynomial in
the raw coefficients is not automatically normalised.
