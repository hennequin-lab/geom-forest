Motors compose like matrices

#ga/motion

Motor.mul m1 m2 is the motion that applies m2 first and m1 second, so the order matches matrices acting on column vectors:

open Geom
let v3 x y z = Nx.create Nx.float32 [| 3 |] [| x; y; z |] in
let sc x = Nx.scalar Nx.float32 x in

let tz = Motor.translate3 0. 0. 1. in
let rz = Motor.rotate ~axis:(v3 0. 0. 1.) ~angle:(sc (Float.pi /. 2.)) in
let m = Motor.mul tz rz in
let same = Motor.compose [ tz; rz ] in
Nx.to_array (Cga.coords (Cga.apply_motor same (Cga.point3 1. 0. 0.)))
(* [|0.; 1.; 1.|]: rotate first, then lift *)

Motor.compose is mul folded over a list, rightmost applied first, and it raises on the empty list rather than inventing an identity. Motor.inverse gives the inverse motion; for a unit motor it is the Clifford conjugate.

Three habits keep composition code correct. Keep the reading order explicit in variable names (shoulder, elbow) rather than relying on comments. Remember that a chain's product accumulates in link-local frames, so the fixed offsets belong between the joint motors (Forward kinematics is a motor product). And renormalise after a long product: float32 drift is small but real, and a motor that is no longer unit makes Motor.translation slightly wrong (Numerical cautions in a projective algebra).
