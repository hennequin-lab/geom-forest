The last axis is the blade axis

#ga/computing

Every value in the library is an ordinary Nx tensor whose last axis is the blade axis, of length , where is the dimension of the algebra. The leading axes are batch axes, broadcast exactly as everywhere else in Nx. So, with , and standing for an arbitrary batch count, height and width:

A constructor such as Cga.point takes coordinates of shape batch @ [|3|] and returns batch @ [|32|]. An extractor such as Cga.coords goes the other way. Products broadcast over the leading axes, which is why the same code maps over a single point, a batch of grasp candidates, or a whole image.

open Geom

let centers = Nx.create Nx.float32 [| 4; 3 |]
    [| 0.; 0.; 0.; 1.; 0.; 0.; 0.; 1.; 0.; 0.; 0.; 1. |] in
let xs = Cga.point centers                               (* [|4; 32|] *)
Nx.shape (Cga.distance2 xs (Cga.point3 0. 0. 0.))        (* [|4|] *)
Nx.to_array (Cga.distance2 xs (Cga.point3 0. 0. 0.))
(* [|0.; 1.; 1.; 1.|] *)

Two consequences for the implementation: the algebra is a batched contraction over the last axis (The multiplication table is 2^n × 2^n signs), and nothing may read a tensor value on the host — a host read would break tracing and differentiable batching (Traced algebra: no host branches).
