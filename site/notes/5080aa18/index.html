Geometric predicates are polynomial

#ga/foundation

Every predicate in this forest is built from sums and products of the coefficients. Incidence is a The left contraction is the metric projection against a blade, distance is a The scalar product reads off a single number, intersection is an wedge, and a transformation is a The sandwich is an algebra automorphism. The only non-polynomial operations are the final square roots and trigonometric functions inside a constructor.

This matters because polynomial residuals are exactly what automatic differentiation wants. There is no case analysis on which object type you have, no coordinate-frame bookkeeping, and no branching on tensor values, so the whole expression is a straight-line program over Nx and it differentiates and compiles (Traced algebra: no host branches).

open Geom

let residual p =
  let x = Cga.point p in
  let pi =
    Cga.plane ~normal:(Nx.create Nx.float32 [|3|] [|0.;0.;1.|])
      ~offset:(Nx.scalar Nx.float32 1.)
  in
  Cga.scalar_prod x pi

let value, grad = Rune.value_and_grad' residual
                    (Nx.create Nx.float32 [|3|] [|0.; 0.; 2.|])
(* value 1., grad [|0.; 0.; 1.|] : the signed distance and its gradient *)

That example is a signed point-to-plane distance: for a point at height and the plane (A plane is a vector). Its gradient is the plane normal; that is not a coincidence, it is the reason these residuals are good objectives (Write task objectives as conformal residuals). The price is numerical care: projective representations carry a scale, and a residual that is polynomial in the raw coefficients is not automatically normalised.
