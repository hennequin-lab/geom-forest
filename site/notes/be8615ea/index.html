Three models, one core

#ga/model

The library is one functor over a A signature counts positive, negative and null directions and a scalar kind, instantiated three times. The algebra never changes; only the interpretation of the blades does. Each row of the table below is a different answer to the question "what should a point be?".

module algebra coeffs objects motions
E3 Cl(3,0,0) 8 vectors, bivectors, volumes rotors (quaternions)
Pga Cl(3,0,1) 16 planes (1), lines (2), points (3) dual quaternions
Cga Cl(4,1) 32 points, spheres, planes, lines, circles, point pairs motors, dilations, transversions

The notation Cl(p,q,r) means a Clifford algebra with positive, negative and null basis directions (A signature counts positive, negative and null directions); the number of coefficients is .

E3 is the rotation algebra: the smallest useful testbed and the orientation layer. PGA adds one degenerate direction so that planes, lines and points become blades and incidence becomes the wedge, at the price of the Hodge dual. CGA adds two dimensions so that Euclidean points become null vectors, which buys distance as an inner product and a complete object layer, at the price of 32 coefficients.

open Geom

(E3.size, Pga.size, Cga.size)                  (* (8, 16, 32) *)
Signature.to_string E3.signature               (* "(3,0,0)" *)
Signature.to_string Pga.signature              (* "(3,0,1)" *)
Signature.to_string Cga.signature              (* "(4,1,0)" *)

The models are not nested implementations of each other: each one has its own object layer, because a CGA point is a null vector and a PGA point is a trivector. What is shared is the packed motor type, which is the even subalgebra of Cl(3,0,1) and the rigid part of Cl(4,1) at once. The trade-offs note says which model to reach for; Four reading paths through the forest says in which order to read them.
